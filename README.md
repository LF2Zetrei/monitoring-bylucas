# monitoring — VPS dashboard

A private dashboard at **`https://monitor.bylucas.eu`** that shows the state
of the VPS and every hosted project, and lets you act on them:

- RAM and disk usage of the server;
- status (`active` / `inactive`) and memory of each project's systemd service;
- status of infrastructure services (nginx, PostgreSQL, fail2ban, Docker)
  and Docker containers (Warp10, Minecraft);
- recent warnings/errors from each service's journal, and a **live log
  stream**;
- **restart** a project's service;
- **re-install / issue the TLS certificate** of a subdomain when it's missing;
- a **Minecraft panel** for the `homestead` server: status, players, memory,
  uptime, start/stop/restart, switch CurseForge modpack, download the world
  as a zip, replace the world with an uploaded zip.

It is a **Next.js server app** (not a static export): its API routes run
`systemctl`, `journalctl`, `docker`, `certbot` and `minecraft-ctl` on the VPS
itself. It has no database: everything it knows comes from two JSON
manifests generated by Ansible, the Minecraft panel config file, and live
system commands.

## 3. Architecture

```
Browser ──HTTPS──▶ nginx (monitor.bylucas.eu)
                    ├─ basic auth (user lucas, /etc/nginx/.htpasswd_monitoring)
                    ├─ rate limit, security headers
                    ├─ body up to 4 GB, no request/response buffering
                    └─ proxy_pass http://localhost:3005  (timeouts 3600 s)
                              │
                              ▼
               monitoring.service (systemd, User=lucas, .env from Ansible)
               └─ npm run start → next start (PORT=3005)
                    ├─ app/page.tsx (sent to the browser, polls the API)
                    └─ app/api/*  (server side, runs as lucas)
                          ├─ fs.readFileSync  /etc/services-manifest.json
                          │                   /etc/infra-manifest.json
                          │                   /proc/meminfo
                          ├─ execFile  systemctl is-active / show
                          ├─ execFile  journalctl -u <name> ...  (spawn for -f)
                          ├─ execFile  docker inspect
                          ├─ execFile  df
                          ├─ execFile  sudo /usr/bin/systemctl restart <name>
                          ├─ execFile  sudo /usr/bin/certbot install|--nginx ...
                          ├─ execFile  docker inspect|stats|exec rcon-cli  homestead
                          ├─ fs        /var/lib/minecraft-panel/config.json (r/w)
                          │            /var/minecraft-uploads/incoming.zip   (w)
                          └─ execFile  sudo /usr/local/sbin/minecraft-ctl <subcommand>
```

The app is just a thin web layer over Linux commands. What it may see and
do is bounded by two things, both generated by Ansible:

1. **What it knows exists** → the manifests (`/etc/*-manifest.json`).
2. **What it is allowed to do as root** → `/etc/sudoers.d/monitoring-restart`
   and `/etc/sudoers.d/minecraft-panel`.

## 4. Data sources: the Ansible manifests

Generated by the `app-deploy` role of `infra/ansible` at every playbook run.

### `/etc/services-manifest.json`

The `projects` list from `infra/ansible/group_vars/all/vars.yml`, as JSON.
Read by `getServices()`; the code only uses these fields (`ServiceConfig`):

```ts
{ name, type: 'node'|'python'|'rust'|'springboot'|'c'|'static', path, subdomain?, port? }
```

### `/etc/infra-manifest.json`

```json
{ "infra_services": ["nginx", "postgresql", "fail2ban", "docker"],
  "docker_containers": ["warp10", "homestead"] }
```

Read by `getInfra()`.

Both readers catch every error (missing file, bad JSON) and return an empty
list → the dashboard shows nothing rather than crashing. Files are re-read
on **every request**, so a new Ansible run is picked up without restarting
the app.

> Adding a project to the dashboard = declaring it in Ansible and running
> the playbook. There is nothing to change in this repo.

## 5. Server side: `lib/` and API routes

### `lib/exec.ts`

| Export | Command | Returns |
|---|---|---|
| `execFile` | `promisify(child_process.execFile)` | Runs a binary with an **argument array**, never through a shell (no command injection possible) |
| `isServiceActive(name)` | `systemctl is-active <name>` | `stdout` (`"active"`), or `"inactive"` if the command exits non-zero |
| `getServiceMemory(name)` | `systemctl show <name> --property=MemoryCurrent` | MB (rounded), or `null` if unavailable (`[not set]` = 2⁶⁴−1) |
| `getContainerStatus(name)` | `docker inspect --format {{.State.Status}} <name>` | `running`, `exited`, ... or `"not found"` |
| `certificateExists(domain)` | `fs.existsSync('/etc/letsencrypt/live/<domain>/fullchain.pem')` | boolean |

### `lib/manifest.ts` — the allow-list

| Function | True when |
|---|---|
| `isKnownAppService(name)` | `name` is a project of the manifest **and not `static`** |
| `isKnownInfraService(name)` | `name` is in `infra_services` |
| `isKnownContainer(name)` | `name` is in `docker_containers` (currently unused) |
| `isKnownSubdomain(domain)` | `domain` is the `subdomain` of a project |

Every route that takes a `[name]` or `[domain]` from the URL checks it
against these first and answers **404** otherwise. That's what prevents
`/api/services/sshd/restart` or `/api/certbot/evil.com/regenerate`.

### API routes

All are App Router route handlers (`route.ts`). Dynamic params are a
`Promise` in this Next.js version (`const { name } = await params`).

| Method & path | Check | What it does | Response |
|---|---|---|---|
| `GET /api/infra` | — | Reads `/proc/meminfo`: `(MemTotal − MemAvailable) / MemTotal`; runs `df --output=pcent /` | `{ ramPercent, ramTotalMB, diskPercent }` |
| `GET /api/infra-services` | — | `isServiceActive` for each infra service, `getContainerStatus` for each container (in parallel) | `[{ name, kind: "systemd"\|"docker", status }]` |
| `GET /api/services` | — | For each project: `static` → `status: "active"`, `memoryMB: null`; otherwise `isServiceActive` + `getServiceMemory`. Plus `certExists` for its subdomain | `[{ ...project, status, memoryMB, certExists }]` |
| `GET /api/services/:name/logs?level=` | app or infra service | `journalctl -u <name> -p <level> -n 100 --no-pager -o json`; `level` must be a syslog level (default `info`). Each JSON line → `{ time (ISO), priority, message }`, newest first. Non-zero exit → `[]` | `LogEntry[]` |
| `GET /api/services/:name/logs/stream` | app or infra service | `spawn('journalctl', ['-u', name, '-f', '-n', '0', '-o', 'json'])`; each line pushed as an SSE event `data: {...}\n\n` through a `ReadableStream`. On client disconnect (`req.signal` abort) the process is killed | `text/event-stream` |
| `POST /api/services/:name/restart` | app or infra service | `sudo /usr/bin/systemctl restart <name>` | `{ success: true }` or 500 |
| `GET /api/certbot/:domain/status` | known subdomain | `certificateExists(domain)` | `{ exists }` |
| `POST /api/certbot/:domain/regenerate` | known subdomain | If the cert files exist: `sudo certbot install --nginx --cert-name <domain>` (puts the HTTPS blocks back into the nginx vhost). Otherwise: `sudo certbot --nginx -d <domain> --non-interactive --agree-tos -m $CERTBOT_EMAIL --redirect` (new certificate) | `{ success: true }` or 500 |

`CERTBOT_EMAIL` comes from the `.env` generated by Ansible (`env_vars` of
the `monitoring` project).

### `lib/guard.ts`

| Export | Purpose |
|---|---|
| `sameOrigin(req)` | `true` only if the `Origin` header's host equals `Host`. Requests with no `Origin` are refused |
| `forbidden()` | `403 { error: 'Origine refusée' }` |
| `audit(action, detail)` | `console.log('[audit] <ISO date> ...')` → ends up in `journalctl -u monitoring` |

### `lib/minecraft.ts`

| Export | Purpose |
|---|---|
| `CONTAINER`, `CONFIG_PATH`, `UPLOAD_PATH`, `MAX_UPLOAD_BYTES` | `homestead`, `/var/lib/minecraft-panel/config.json`, `/var/minecraft-uploads/incoming.zip`, 4 GB |
| `readConfig()` | `{ slug, fileId }` from `config.json` (empty strings on error) |
| `validConfig(slug, fileId)` | slug `^[a-z0-9][a-z0-9-]{0,79}$`, fileId empty or 1–10 digits (same regexes as `minecraft-ctl`) |
| `ctl(sub)` | `sudo /usr/local/sbin/minecraft-ctl <sub>`, 10 min timeout. `sub` is a fixed union type matching the sudoers lines |
| `getStatus()` | `docker inspect` (state, health, start time, `CF_SLUG` env), and if running `docker stats` (memory) + `docker exec homestead rcon-cli list` (players) |

### Minecraft routes

Every route that changes something calls `sameOrigin` first (403
otherwise) and writes an `audit` line on success.

| Method & path | What it does | Response |
|---|---|---|
| `GET /api/minecraft` | `getStatus()` + `readConfig()` | `{ status, health, startedAt, memory, players, runningSlug, config }` (`status: "absent"` if no container) |
| `POST /api/minecraft/power` | Body `{ action: "start"\|"stop"\|"restart" }` → `ctl(action)` | `{ success: true }`, 400 unknown action, 500 |
| `POST /api/minecraft/modpack` | Body `{ slug, fileId?, clean? }`, validated → writes `config.json` (0600) → `ctl('apply-clean' \| 'apply')` | `{ success: true }`, 400 invalid, 500 |
| `GET /api/minecraft/world/download` | `spawn('sudo', ['minecraft-ctl', 'export-world'])`, stdout streamed as `homestead-world-<date>.zip` (`X-Accel-Buffering: no`) | `application/zip` |
| `PUT /api/minecraft/world/upload` | Raw zip body streamed to `incoming.zip` (0600) through a byte counter; aborts and deletes the file above 4 GB. Applies nothing | `{ success, bytes }`, 413 too large, 500 |
| `POST /api/minecraft/world/import` | `ctl('import-world')`: validation, stop, backup, swap, start (see the `minecraft-homestead` role in the infra README) | `{ success: true }`, or 400 with the last stderr line of the script (e.g. `level.dat introuvable...`) |

Download is not origin-checked: it is a plain link (`GET`) and only reads.

## 6. Client side: the dashboard

### `app/page.tsx` (client component)

- On mount, and then every **15 s** (`REFRESH_INTERVAL_MS`), fetches
  `/api/infra`, `/api/services` and `/api/infra-services` in parallel and
  stores the results in state. (The first call is scheduled in a microtask
  so the effect never calls `setState` synchronously.)
- Derives `alertsCount` = number of projects whose status isn't `active`.
- Renders:

```
Monitoring                                    bylucas.eu
┌────────┐ ┌────────┐ ┌──────────┐ ┌─────────┐
│ RAM    │ │ Disque │ │ Services │ │ Alertes │   ← MetricCard ×4
│ 63%    │ │ 41%    │ │ 6 / 7    │ │ 1       │     (Alertes turns red if > 0)
│ ▓▓▓▓░░ │ │ ▓▓░░░░ │ └──────────┘ └─────────┘
APPLICATIONS
 ● catlendar   node · :3004                    ▾   ← ServiceAccordion per project
 ● landing     static                          ▾
 ...
MINECRAFT
 ● Homestead running · healthy        [Redémarrer] [Arrêter]   ← MinecraftPanel
 JOUEURS 0 / 20   MÉMOIRE 4.1GiB   UPTIME 23 j   MODPACK homestead-cozy
 CHANGER DE MODPACK  [slug] [file ID] [x] Nettoyer...  [Appliquer]
 MONDE  [Télécharger le monde (.zip)] [Remplacer le monde…]
INFRASTRUCTURE
 [nginx] [postgresql] [fail2ban] [docker] [warp10] [homestead]  ← InfraTags
```

The UI text is in French ("Disque", "Alertes", "Redémarrer"...).

### `components/MetricCard.tsx`

Tile with a label, a big value, an optional progress bar (`percent`) and an
optional red `accent`.

### `components/InfraTags.tsx`

One tag per infra service/container: white background when `active`
(systemd) or `running` (Docker), pink otherwise. Display only, no actions.

### `components/ServiceAccordion.tsx`

One row per project; click to expand.

- **Header**: colored dot (`active` green, `failed` orange, otherwise gray),
  name, type, port.
- **On first expand**: fetches `/api/services/<name>/logs?level=warning`
  (warnings and worse only) and caches the result in state.
- **Details**: memory (MB), status, domain.
- **Logs** (non-static only): colored by syslog priority (0–3 red, 4
  amber, 5+ gray), times in `fr-FR`.
- **"Voir en direct"**: opens an `EventSource` on `/logs/stream`, prepends
  each event to `liveLogs` (capped at 100 lines). Clicking again, collapsing
  the row or unmounting closes the `EventSource` → the server kills its
  `journalctl -f`.
- **"Redémarrer"** (non-static): `POST /api/services/<name>/restart`, shows
  "Redémarré" or an error message. The status refreshes at the next 15 s poll.
- **"Régénérer le certificat SSL"**: only shown when `certExists === false`;
  `POST /api/certbot/<subdomain>/regenerate`.

### `components/MinecraftPanel.tsx`

Self-contained: polls `/api/minecraft` every **10 s** on its own.

- **Header**: dot (`running` green, `exited` gray, `absent` orange), status
  and health; "Démarrer" when stopped, "Redémarrer" / "Arrêter" (with
  confirm) when running.
- **Stats**: players, memory used, uptime, running modpack (`CF_SLUG` of the
  container).
- **Changer de modpack**: CurseForge slug + optional file ID (pre-filled
  once from `config.json`), "Nettoyer mods/ et config/" checkbox (checked by
  default, recommended when switching to another modpack). Confirm →
  `POST /modpack`. The server then re-downloads the modpack (a few minutes).
- **Monde**: "Télécharger" is a link to `/world/download` (hot copy, autosave
  paused a few seconds). "Remplacer le monde…" picks a `.zip`, confirms,
  sends it with `XMLHttpRequest` `PUT /world/upload` (progress shown in %),
  then `POST /world/import`. The zip may contain the world folder or its
  content directly; it must contain `level.dat`.

## 7. Security model

| Layer | Protection |
|---|---|
| Network | Port 3005 is blocked from the outside by UFW; only nginx (localhost) reaches the app |
| nginx | **Basic auth** is the only authentication — the app itself has none. Plus HTTPS, rate limit (10 req/s, burst 20), security headers |
| Input validation | Every `[name]` / `[domain]` must be in the Ansible manifests (404 otherwise); `level` must be a known syslog level |
| Command execution | `execFile` / `spawn` with argument arrays, no shell → no injection |
| Privileges | Runs as `lucas`, not root. Root actions are limited to the exact commands listed in `/etc/sudoers.d/monitoring-restart` and `/etc/sudoers.d/minecraft-panel` |
| Minecraft root actions | Only through `minecraft-ctl` with fixed subcommands; the modpack values it reads from `config.json` are re-validated there, uploaded zips are checked (paths, `level.dat`, size) before use, and the old world is backed up first |
| CSRF | Minecraft write routes require `Origin` = `Host` (`lib/guard.ts`) |
| Audit | Minecraft actions are logged: `journalctl -u monitoring \| grep audit` |
| Resources | Live log processes are killed when the client disconnects; uploads are capped at 4 GB |

Note: the older `POST` routes (`services/.../restart`, `certbot/...`) still
have no CSRF protection. With basic auth the browser re-sends credentials
automatically, so a malicious page visited while logged in could trigger a
restart. Calling `sameOrigin` from `lib/guard.ts` there would close it.

## 8. Permissions required on the VPS

The app runs as `lucas` (systemd `User=lucas`). What each feature needs:

| Feature | Needs | Provided by |
|---|---|---|
| Read manifests | Read `/etc/*-manifest.json` (0644) | Ansible |
| `systemctl is-active` / `show` | Nothing (unprivileged) | — |
| `docker inspect` | `lucas` in the `docker` group | Ansible `docker` role |
| `journalctl -u <unit>` for system units | `lucas` in `systemd-journal` (or `adm`) group | **Not configured by Ansible** — see §11 |
| Restart a project | sudoers `systemctl restart <project>` | Ansible `app-deploy` |
| Restart an infra service (nginx...) | sudoers entry for it | **Not present** — see §11 |
| `certbot install` | sudoers `certbot install --nginx --cert-name <subdomain>` | Ansible `app-deploy` |
| First certificate issuance | sudoers for `certbot --nginx -d ...` | **Not present** — see §11 |
| `certificateExists` | Traverse `/etc/letsencrypt/live/` | Root-only by default — see §11 |
| Minecraft status / players | `docker inspect`, `docker stats`, `docker exec ... rcon-cli` (`docker` group) | Ansible `docker` role |
| Minecraft config / upload | Write `/var/lib/minecraft-panel/` and `/var/minecraft-uploads/` (owned by `lucas`, 0700) | Ansible `minecraft-homestead` |
| Minecraft actions | sudoers `minecraft-ctl start\|stop\|restart\|apply\|apply-clean\|export-world\|import-world` | Ansible `minecraft-homestead` |
| World upload/download | nginx `client_max_body_size 4g`, no buffering (`large_transfers: true`) | Ansible `app-deploy` (added by hand on the current VPS, see infra README §11) |

## 9. Deployment and hosting

```
git push main
  └─ .github/workflows/deploy.yml
       uses LF2Zetrei/infra-github-actions/.github/workflows/reusable-deploy.yml@main
       with project_name=monitoring, project_type=node, remote_path=/home/lucas/apps/monitoring
         ├─ rsync repo (minus .git, node_modules, .env) → /home/lucas/apps/monitoring
         ├─ on the VPS: npm ci && npm run build
         ├─ sudo systemctl restart monitoring
         └─ systemctl is-active monitoring
```

Ansible declaration (`infra/ansible/group_vars/all/vars.yml`):

```yaml
- name: monitoring
  type: node
  path: /home/lucas/apps/monitoring
  subdomain: monitor.bylucas.eu
  port: 3005
  basic_auth: true
  basic_auth_user: lucas
  basic_auth_password: "{{ vault_monitoring_password }}"
  proxy_timeout: 3600          # long timeout so live log streams aren't cut after 60 s
  large_transfers: true        # 4 GB bodies, no buffering (Minecraft world upload/download)
  env_vars:
    PORT: "3005"
    CERTBOT_EMAIL: "..."
```

Ansible creates the `.env`, `monitoring.service` (`ExecStart=/usr/bin/npm run start`),
the nginx vhost with basic auth, the certificate, the manifests and the
sudoers file. Restarting the monitoring service from its own dashboard works
(it's in the sudoers) but cuts the page until it's back.

## 10. Local development

```bash
npm ci
npm run dev       # http://localhost:3000
npm run lint
npm run build && PORT=3005 npm run start
```

Locally, the manifests don't exist, so the lists are empty and actions
return 404. To get data, create test manifests (requires root, or
temporarily change the paths in `lib/manifest.ts`):

```bash
echo '[{"name":"cron","type":"node","path":"/tmp","subdomain":"localhost","port":1}]' | sudo tee /etc/services-manifest.json
echo '{"infra_services":["ssh"],"docker_containers":[]}' | sudo tee /etc/infra-manifest.json
```

`/api/infra` works anywhere on Linux (`/proc/meminfo`, `df`).

## 11. Known issues and limitations

These come from reading the code against the Ansible configuration; check
them on the VPS before fixing.

- **Restarting infra services fails**: the restart route accepts infra
  services (`nginx`, `postgresql`...), but the sudoers only lists project
  services → `sudo` asks for a password and fails (HTTP 500). The UI has no
  button for infra anyway. Either add sudoers entries for them in
  `monitoring-sudoers.j2` or restrict the route to `isKnownAppService`.
- **First certificate issuance fails**: the "else" branch of
  `regenerate` runs `sudo certbot --nginx -d ...`, which isn't in the
  sudoers. Only `certbot install` (re-install of an existing cert) works.
  The sudoers also allows `certbot renew --force-renewal`, which no route
  uses.
- **Certificates probably always reported missing**: Certbot creates
  `/etc/letsencrypt/live/` with mode 0700 (root only), so `fs.existsSync`
  run as `lucas` returns `false` even when the cert exists → the
  "Régénérer le certificat SSL" button would appear on every project.
  Check with `sudo -u lucas test -e /etc/letsencrypt/live/<sub>/fullchain.pem; echo $?`.
  Fix options: check the expiry via `openssl s_client` instead, or let
  `lucas` read the directory (e.g. a group with `chmod 0750`).
- **Logs may be empty**: unprivileged users only see their own journal.
  Unless `lucas` is in `systemd-journal` (or `adm`), `journalctl -u nginx`
  returns nothing, and the route turns that into `[]`
  ("Aucun avertissement ou erreur récent"). Add the group in the Ansible
  `ssh-hardening` or `docker` role (`groups: [docker, systemd-journal]`).
- **`failed` is never displayed**: `systemctl is-active` exits non-zero for
  any non-active state, so `isServiceActive` returns `"inactive"` even when
  stdout was `"failed"`. Read `stdout` from the caught error to keep the
  real state.
- **Minecraft panel locally**: there is no `homestead` container nor
  `minecraft-ctl`, so the panel shows `absent` and every action fails.
- **Minecraft world upload needs free disk space** for the zip plus the
  unzipped world plus a backup, all on the VPS disk.
- **Static projects always "active"**: no check is made that the folder
  is non-empty or that the site answers. An HTTP check against
  `https://<subdomain>` would be more honest.
- **"Services" count includes static sites**, which are always counted as up.
- **No history / alerting**: values are instantaneous; nothing is stored,
  and nobody is notified when a service goes down.
- **Tailwind is installed but unused**; styles are inline.
